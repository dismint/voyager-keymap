# Lighting

The top two rows have blacked-out keycaps with no LED shine-through, so only the bottom two rows and the thumb keys light up — 28 keys total. Each layer gets one pastel visual pattern across those 28 keys, not per-key colors, so the layer is identifiable by shape at a glance:

- **Base** — white, dim top row / bright bottom row + thumbs.
- **Sturdy** — flat pastel purple across both hands, no gradient.
- **Symlayer** — pastel blue outline: just the outer corners of the top row, the entire bottom row, and both thumbs — a frame around the bottom and edges.
- **ArrowFN** — pastel green arrow shape: the entire bottom row plus the inner top-row key and both thumbs per hand, angling in toward the center.
- **Gaming** — pastel rainbow sweep across the left hand only (right hand's on the mouse, stays dark).
- **Numpad** — flat pastel teal across the entire right hand, left hand dark.

# Moonlander port

`keymap-moonlander/keymap.c` is generated, not hand-written. `scripts/generate_moonlander.py` re-maps every key and color from the Voyager source onto the Moonlander's layout; `scripts/build.sh moonlander` runs it automatically before compiling.

The Moonlander has more physical keys than the Voyager per half. The extras are left dark and unbound: the 3-key column next to each thumb cluster, the entire bottom row, and the innermost of each thumb cluster's three keys. Everything else maps one-to-one with the Voyager layout above.

# Repo layout

```
keymap/                 Voyager source — keymap.c, config.h, rules.mk, keymap.json.
                         The single source of truth, symlinked into qmk_firmware.
keymap-moonlander/      Moonlander keymap, generated — don't edit by hand.
layout/                 Generated SVG diagrams for the section above.
flake.nix, flake.lock   pinned build environment (qmk CLI, ARM toolchain) — see below.
scripts/
  setup.sh               one-time environment setup for both boards
  build.sh               build + stage a flashable .bin: `build.sh [voyager|moonlander]`
  generate_moonlander.py derives the Moonlander keymap from the Voyager one
  render_layouts.py      renders keymap.c into the diagrams above
  arg_to_led.py          maps a key's position to its LED index (see CLAUDE.md)
  render_ledmap.py       turns a list of colors into a ready-to-paste ledmap[] row
CLAUDE.md               notes for anyone (human or otherwise) working on this repo
```

# Building and flashing

The whole toolchain — `qmk`, the ARM compiler, Python deps — is pinned in `flake.nix`/`flake.lock`. No floating nixpkgs channel involved, so a build today and a build in a year use the exact same versions. Only prerequisite is Nix itself.

```sh
./scripts/setup.sh               # once, clones and patches qmk_firmware
./scripts/build.sh                # Voyager
./scripts/build.sh moonlander     # Moonlander
```

The `.bin` lands in `build/` and gets copied to the Windows Downloads folder, if present. Flash it with **Keymapp** (Wally is deprecated).

To update the pinned toolchain: `nix flake update`, then rebuild both boards before committing `flake.lock`.
